# 双目视频流调焦与引导标定

适用本机 USB 同帧左右拼接相机：总图 `2560×960`，每目 `1280×960`。
棋盘为 **12×9 squares / 11×8 inner corners / square 20 mm**。当前软件完成流程实现；
2026-09-16 已完成 30 组真实棋盘采集并应用新标定，留出几何验证通过；独立距离精度仍待验证。

## 1. 启动与部署

固定设备目录 `/home/gmaster/boom_birds_ws/stereo_depth`。部署直接覆盖更新文件，不创建旧工程副本；
先比对远程改动，停止被更新的程序，保留 `calibration/`、`captures/`、`depth_outputs/` 测量数据。

运行文件：`live_calibration.py`、`calibration_core.py`、`calibration.html`，依赖 Python 3、NumPy、OpenCV 4.6+。
`test_live_calibration.py` 是无硬件回归检查。`depth_preview.py` 用于后续加载新标定测试深度。
没有增加 pip、ROS 或 Web 框架依赖。

停止占用相机的深度程序后，在 **Windows PowerShell** 执行：

```powershell
ssh -t -L 18082:127.0.0.1:8082 gmaster@192.168.137.200 "cd /home/gmaster/boom_birds_ws/stereo_depth && python3 live_calibration.py"
```

打开 <http://127.0.0.1:18082/>。保持窗口，`Ctrl+C` 停止；关闭浏览器不停止程序。
若 Codex 已启动预览，直接访问，不要再起第二个实例。
在 VS Code Remote-SSH 终端也可运行 `python3 live_calibration.py`，再转发远程端口 `8082`。

## 2. 原图调焦

1. 纸张贴在平整硬板上，完整黑白格外围保留白边。量连续 10 格应为 **200 mm**。
   12×9 个 20 mm 方格的外尺寸为 240×180 mm；A4 仅表示纸张尺寸，不能代替实测。
2. 棋盘放在预期工作距离。画面 A/B 是拼接左/右半幅，不对画面镜像。
3. 选择“原始高分辨率”。这是设备原始 JPEG 字节，未经校正、缩小或二次压缩。
4. 点击任一目的图像，分别选择局部区域。下方 320×240 裁切来自原始像素，宽屏下按 1:1 显示。
   小屏会缩小显示，查看精细边缘建议在电脑宽屏操作。
5. 分别调节镜头，使黑白边缘清晰，兼顾画面中心和边缘；检查实际工作距离范围。
   定焦镜头旋转镜筒通常是在调焦，不是直接改变标称焦距。
6. 双目识别棋盘后，页面提供边缘过渡宽度（px）；相同距离和光照下越小越清晰。
   数字受运动、曝光、纹理与板大小影响，只是辅助，不是绝对焦距或画质验收。

采集期间不得再转动镜头或改变两目相对安装位置。若调整过，重置本轮重新采集。

## 3. 自动采集

勾选尺寸、平整度和调焦确认，再点“开始自动采集”。程序不需要手动保存照片。
角点检测先在小图搜索，然后在原始分辨率细化；两目角点始终来自同一原始拼接帧。

采集自动检查：两目完整检测、足够棋盘尺寸、离边界的余量、棋盘边缘锐度、连续稳定、
相邻收样时间间隔和姿态差异。正常摆法：

- 中心开始，依次移到上下左右和四角，两目都保留完整棋盘及外白边。
- 改变远近；每个位置停稳约 1 秒，等待“已收集”计数增加。
- 补充左右转面、上下俯仰约 15–35°，以及少量平面内旋转。
- 根据实时提示补缺少的覆盖；至少 24 组，最多 60 组后自动暂停。

“计算标定”门槛：每目 4×3 区域至少覆盖 9 格；棋盘中心覆盖 3×3 区域至少 5 格；
棋盘线性尺寸跨度至少 1.5 倍；至少 6 个倾斜特征姿态；平面转角跨度至少约 20°。
这些是便于操作的几何启发式，不代表所有镜头都已获得充分约束。
收样拒绝阈值包括角点行间距约 12 px、棋盘过渡宽度 3.5 px、检测间运动 RMS 2.5 px。
页面实时提示拒绝原因；不要为了凑数量重复摆同一姿态。

## 4. 计算和检查

点击计算后，视频继续显示。计算每目内参及五参数畸变模型，然后固定内参求双目 `R/T`，
生成校正 `R1/R2/P1/P2/Q`。每 5 组固定留出 1 组，不参与拟合，报告单目重投影与双目校正垂直误差。
当前模型为普通针孔模型，不是专用鱼眼模型；边缘误差明显时需复查镜头模型和覆盖。

估计基线从 20 mm 棋盘物点计算，**不会强制缩放为旧的 65 mm**。
若与历史 65 mm 相差超过 10%，报告会提示检查打印比例和安装尺寸。
训练 RMS >1 px、留出垂直 P95 >1.5 px、留出单目 RMS >1.5 px 等会产生复查提示。
这些阈值在原始每目分辨率下使用，只是工程筛查。

完成后选择“校正后 + 水平线”，摆放尚未采集的新姿态，检查同一角点在两目是否位于同一水平线。
页面会显示当前识别帧的垂直误差；这不是对原始视频做畸变前后锐度比较的视图。

结果目录 `calibration/live_<时间>/`：

| 文件 | 含义 |
| --- | --- |
| `observations.npz` | 自动原子更新的两目角点、帧序号、图像尺寸、棋盘参数；无原始照片 |
| `candidate.npz` | 内参、畸变、双目几何与校正矩阵；距离单位为米 |
| `report.json` | 训练/留出索引、误差、覆盖、基线与警告 |

这些是测量记录，不是工程旧版本。新结果不自动覆盖历史标定。
刷新网页不会清空服务器内存；停止/重启进程后不会自动恢复采集，磁盘角点仍保留供分析。
重置本轮只清当前会话，不删除已保存测量记录。计算中不能重置。
只留角点意味着无法事后对原图换算法重新检测；需要重新检测时重新采集视频即可。

## 5. 用新标定验证深度

停止校准服务以释放相机，再在树莓派项目目录运行（替换为页面显示的实际路径）：

```bash
python3 depth_preview.py --calibration calibration/live_实际时间/candidate.npz
```

深度程序按标定的 `image_size` 请求相同采集模式，再缩放内参、重算校正映射，输出仍为完整 XYZ/Z `320×240`。
不假定相机所有分辨率模式的裁剪/视场一致。高分辨率采集的性能需重新实测。
未提供 `--calibration` 时默认使用 `calibration/live_20260916_210120_642136/candidate.npz`，基线估计 67.6718 mm，采集 `2560×960`。旧标定保留为历史测量证据。
换用标定后请通过 SSH 转发 `8081`，在多个已知距离、不同画面位置独立测量误差。
几何报告通过不代表米制精度、避障或飞行验收通过。

## 6. 文件职责与检查

- `calibration_core.py`：棋盘检测、角点排序、质量/覆盖评价、几何求解和留出验证。
- `live_calibration.py`：最新帧采集、独立预览/检测线程、会话状态、角点持久化、HTTP。
- `calibration.html`：原图、可点选局部裁切、指引、覆盖与报告。
- `test_live_calibration.py`：合成几何与尺度、真实算法棋盘检测、HTTP 门槛、首帧等待、深度加载兼容测试。

```bash
python3 -m unittest -v test_live_calibration
```

算法 API 依据 [OpenCV 相机标定与三维重建](https://docs.opencv.org/4.7.0/d9/d0c/group__calib3d.html)。
UI 的相机 FPS 是取帧速率；原图浏览器流默认最多 15 FPS（`--stream-fps`），检测叠加流取决于检测耗时。
这不修改原深度程序的不限输出帧率策略。

### 低延迟预览与后台恢复（2026-09-16）

网页现在逐帧请求 `/frame/raw.jpg` 等最新图像，显示/解码完成后再请求下一帧，最多一个请求在途。
切换视图会取消旧请求；页面隐藏时暂停取图。原图仍为设备 JPEG 原字节、2560×960，不降低分辨率。
检测用的后台解码最多 8 FPS；调焦阶段减少检测频率，并关闭额外的 SB 搜索回退，正式采集仍保留该回退。
旧 `/stream/*` 端点兼容保留；更新后须刷新网页，才能停止旧的连续流。

页面“传输＋解码”是浏览器一次取帧至图像解码完成的时间；“估计帧龄”加上设备收到该帧到服务响应前的时间，
近似且略保守，**不包含传感器曝光和驱动内部缓冲，不是端到端测量**。
现场短时检查 CPU 从原约 203% 降至约 88%；某次浏览器显示传输＋解码 121 ms、估计帧龄 130 ms。
数值随 Wi-Fi 和场景改变，不作延迟保证。

